# Временный HTTPS для Bitrix24

Для подключения тестового портала зарегистрируйте серверное локальное приложение с правами `task` и `user`. Не включайте «Приложение само завершает установку»: первоначальная установка не принимает и не сохраняет токены. Адрес обработчика — `https://YOUR-HOST/oauth/bitrix24/callback`. Кнопка CallMind запускает отдельный полный OAuth-вход после регистрации.

В игнорируемом Git файле `credentials-bitrix24.json` укажите `client_id`, `client_secret`, `portal_url` и `public_base`. Переменные `BITRIX24_CLIENT_ID`, `BITRIX24_CLIENT_SECRET`, `BITRIX24_PORTAL_URL`, `BITRIX24_PUBLIC_BASE` имеют приоритет. Адрес Bitrix24 отделён от `CALLMIND_OAUTH_PUBLIC_BASE`, поэтому локальный вход Google не меняется.

`tools/oauth_gateway.py --port 8780 --upstream-port 8770` слушает только loopback. Он пропускает GET-запросы исключительно на `/oauth/bitrix24/callback`. Интерфейс Streamlit, API, начало входа, файлы и callback Google через этот шлюз недоступны. Запросы с кодами не журналируются.

Временный туннель направляется на порт шлюза 8780, а не на Streamlit. Запуск требует явного разрешения пользователя на передачу кода OAuth через конкретного провайдера туннеля. Публичный адрес временный: после остановки или изменения адреса нужно обновить регистрацию Bitrix24 и `public_base`. На постоянном сервере используется стабильный HTTPS reverse proxy.

Подключение только проверяет текущего пользователя и сохраняет токены на стороне CallMind. Создание или изменение задачи выполняется после подтверждения договорённости и явного выбора переноса.
