# CallMind: реализованная переработка панели

Обновление Google Calendar: двусторонняя сверка связанных событий, независимая автосинхронизация, защита etag, конфликты и настройки отдельного события. Реальный цикл и доставка уведомления на телефон подтверждены; тестовые события отменены. Подробности: [CALENDAR_SYNC_SPEC.md](CALENDAR_SYNC_SPEC.md).

Обновление 06.10.2026: перенос и сверка клиентов/задач, выбор сделок и импорт результатов CRM описаны в [CRM_SYNC_SPEC.md](CRM_SYNC_SPEC.md). Проверено 67 тестов на отдельной SQLite и сетевых заглушках. Формы клиентов проверены на 1280 px и 390 px; ширина страницы на телефоне 390 px, кнопка сохранения 44 px. Реальные клиентские данные в CRM при проверке не отправлялись. Старые замечания о неподключённом импорте ниже относятся к предыдущему этапу.

Основание: доступный снимок предыдущей панели `callmind-preview.png`, файлы текущего проекта и требования пользователя. Новых прикреплённых изображений в последнем сообщении нет. Наблюдения на снимке, подтверждения кодом и гипотезы разделены ниже. Пользовательское исследование не проводилось.

## Что работает

- Навигация: Обзор, Звонки, Клиенты, Сделки, Аналитика, Настройки. Добавление звонка доступно в шапке, экспорт вторичен.
- Список без повторов: действие, клиент, срок, статус, проверка. Сначала просрочки, затем сегодня, остальные сроки и задачи без даты. Фильтры статуса, срока и стороны независимы, текущий выбор подписан даже при свёрнутых фильтрах.
- Детали: цитата, исходный срок, аудио с реальной отметки только при совпадении цитаты с сегментом и текущим текстом, переходы к звонку, клиенту и явно связанной сделке. Сырые ревизии сохраняются, история отображается человеческим текстом.
- Редактор с динамическими полями, предупреждением о черновике, возвратом к нему или отменой. Черновик хранится в сессии Streamlit, не переживает закрытие сессии / перезапуск сервера. Несохранённые правки блокируют выполнение и синхронизацию этой задачи.
- Сообщение «Сохранено в CallMind» отдельно от внешних подтверждений. Два сервиса имеют независимые сохранённые сообщения, включая ошибки подключения до создания удалённого объекта. Состояние после локальной правки становится требующим повторной проверки.
- CRM назначает задачу настроенному сотруднику независимо от стороны обязательства. По уточнению пользователя автоматическая отправка полностью отключена, включая старую сохранённую настройку. После сохранения и «Подтвердить» доступны три направления: «Перенос» в оба сервиса, только CRM или только календарь. Сохранение, анализ и выполнение ничего не отправляют. Сервер тоже требует актуального подтверждения проверки.
- Встреча → событие с занятостью; задача → напоминание без занятости. Без точного времени — весь день, без срока — не создавать новое событие. Удаление срока отменяет прежнее при синхронизации. Выполнение задачи отменяет напоминание; выполненная встреча остаётся в истории. Google Calendar и ICS используют одинаковые правила. Это события Calendar API, не интеграция Google Tasks.
- Сделки: создание, неизвестная сумма допустима, явные связи со звонками / договорённостями, выигрыш / проигрыш / повторное открытие, обязательная причина проигрыша и фактическая дата. Источник результата — человек, указанное имя не является удостоверенной корпоративной учётной записью. История событий сохраняется.
- Аналитика: период и определения, клиент / приоритет / тип договорённостей, текущие проверенные просрочки, сегодня, без срока, проверка, проблемы сервисов; события выполнения; соблюдение первого подтверждённого срока. Новые результаты сделок, доля побед, суммы и средние отдельно по валютам, медиана времени закрытия, подтверждённые причины. Показатели раскрывают исходные записи.
- Повторное открытие сохраняет прежний ID; исторический отчёт сделок берёт последнее событие на конец периода. Перенос срока не стирает первый подтверждённый срок. Старые данные без подходящего подтверждения не превращаются в выдуманные показатели.
- API сохранён и дополнен защищёнными маршрутами сделок, связей, подтверждения проверки и аналитики. Новые таблицы создаются дополнительно, исходные таблицы не перестраиваются.

## Проверка

36 автоматических проверок проходят: существующие сервисы и API, экспорт, календарная семантика, защита повторных отправок, разделение ошибок сервисов, сделки / повторное открытие / исторические периоды, подтверждённые сроки, пустой список, ошибка AI, динамические поля срока, ошибка сохранения и сохранность черновика при переходах. Дополнительно проверены три направления переноса, частичная ошибка, серверная блокировка без подтверждения и отсутствие неявной отправки при старом auto_sync=true. Используются временная SQLite и сетевые заглушки.

Браузерный стенд — `.test-data/redesign`, полностью синтетический клиент и записи, `auto_sync=false`. Записи и данные рабочих клиентов не отправлялись внешним сервисам ради анализа или проверки.

Проверяемые ширины: 1280 и 390 px. На телефоне основные кнопки имеют высоту не менее 44 px; длинные названия переносятся, горизонтальное переполнение всей страницы отсутствует. Снимки лежат в каталоге артефактов Codex и показывают тестовые данные.

## Оставшиеся зависимости и ограничения

1. Реальные подтверждения Bitrix24 / Google Calendar требуют вебхука, ID сотрудника и OAuth. Живые аккаунты не использовались: корректность взаимодействия проверена заглушками, доступ конкретного портала / аккаунта ещё нужно проверить.
2. Импорт результатов сделок из Bitrix24 не реализован. Нужны права CRM, внешние ID, сопоставление клиентов и стадий по семантике, история закрытий / повторных открытий. Ручной результат не выдаётся за результат CRM.
3. Нет корпоративной модели пользователей, ролей или назначения задач разным менеджерам; имена в журнале ручных результатов не являются авторизацией. Старые правки не имеют автора, UI это указывает.
4. Детали — отдельный экран внутри Streamlit с возвратом к списку, без постоянно закреплённой боковой панели. Импортированные Python-модули требуют перезапуска сервера после обновления.
5. AI/ASR оставлены существующими. Окружение интерфейса не включает веса Whisper и пакеты текущего Gemini. Замена на Qwen3-8B-Q4_K_M, обучение и отдельная проверка качества остаются задачей модели, а не частью этой переработки.
6. Для ошибок обработки звонков есть понятное сообщение, но пока нет серверного журнала job и повторного запуска отдельного этапа; поэтому аналитика частоты / времени ошибок AI недоступна. Прогнозы влияния на продажи и экономии времени не рассчитываются.
7. Смена календаря / портала не очищает записи старого аккаунта автоматически. Подтверждения отображают время последней попытки; повторная синхронизация проверяет текущую конфигурацию. Историческая доля соблюдения сроков для старых записей неполна.

Документация календарных полей и частичного обновления: [Events resource](https://developers.google.com/workspace/calendar/api/v3/reference/events), [Events patch](https://developers.google.com/workspace/calendar/api/v3/reference/events/patch).


Подключение через настройки: добавлены две отдельные OAuth-кнопки, обработчик возврата, одноразовый state на 10 минут, проверка календаря/пользователя и серверное сохранение токенов. Подключение не запускает перенос. Проверены отмена, неверный провайдер, истечение ссылки, повтор callback и независимость сообщений. Для реального входа нужны зарегистрированные приложения; Bitrix24 требует HTTPS callback и настроенный прокси. Проверена ширина 390 px: горизонтальное переполнение страницы отсутствует.
